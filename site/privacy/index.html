Privacy notice

Draft published for review. Last updated 23 October 2026.

This page is a draft. It has not been reviewed by a lawyer and it is not final.

1. Who we are

KithMoot is open-source software published by ForgeSworn. This notice describes what our public website and update service handle, the independent services the apps contact, and the settings kept on your device. Our former public call relay and STUN service are closed. Private deployments arranged separately have their own operator and access arrangements (section 4.5). For UK data protection law we are the controller of the data our public website and contact route handle.

To ask about anything on this page, write to abuse@safety.forgesworn.dev.

Legal basis. The little we handle is the address a web request comes from and any correspondence you send us. Our basis for it is legitimate interests (UK GDPR Article 6(1)(f)): we need it to run the app, this website and the update service, and to answer you. We collect nothing else. You can object to this use by writing to the address above.

2. The short version

  • KithMoot encrypts room content on participants' devices. The public website and update service do not receive room messages, files or call media. A call relay you select carries encrypted packets (section 4.5).
  • kithmoot.forgesworn.dev serves the app, this website and update information as static files. Recent client source uses Cloudflare STUN, unless you choose another server. Older installed versions may still name our former listener, which stopped on 23 October 2026 (section 4.3).
  • Until 22 October 2026 we also ran a public call relay, a file store, a message-drop service and meeting codes. Those public services are closed. Their data and retained backups are described in section 4.4 and the closure record. This does not mean that separately arranged private deployments have all stopped.
  • In the web app and the desktop app, files you send go to a public file server run by somebody else, unless you choose another server or none. They are encrypted on your device first (section 7).
  • Some defaults make your device contact other parties: relays, profile lookups, picture hosts and, for the desktop app, our site and GitHub (section 7). You can turn the profile lookups off.
  • We do not sell your data, show adverts, or run analytics or tracking.

3. Things we never collect

  • Your private key. Never sent to us in any KithMoot flow.
  • Room content at the public website. The website and update service do not hold room traffic keys. Participants' devices hold the keys needed to open their room's content; a separately selected TURN relay is not given the WebRTC media session keys.
  • A membership list. There is no server-side record of who is in a room.
  • Card or bank details. KithMoot has no payments functionality.

4. What our server sees, and why

4.1 The web server

Our web server serves the app, this website and the downloads. Like any web server it sees the address a request comes from, the time and the file asked for. ForgeSworn's host keeps no access logs for either KithMoot site, including for the automatic redirect from plain HTTP to HTTPS (as of 23 October 2026). Your address is therefore not written down there.

4.2 Update checks from the desktop app

Every desktop build except the Debian package checks our site for updates, 30 seconds after it starts and then on a timer: every ten minutes for the signed app for Macs with Apple silicon, and every hour for the Windows ZIP and the Linux tar.gz. When there is an update, the app downloads it from our site too. Each check is an ordinary request for a static file, so our web server sees the address it came from, the time, and the file it asked for, which says what kind of build is asking. There is no setting to turn the checks off. The access log is discarded (section 4.1). The Debian package does not check by itself: the system's package manager fetches its updates from GitHub (section 7).

4.3 STUN

STUN tells a device its own public address, so a call can try to connect directly. Our former public listener stopped on 23 October 2026. Older installed clients, including Android through 0.6.105 and desktop through 0.1.101, may still name it. Desktop 0.1.102 and Android 0.6.106 move those defaults to Cloudflare; a web deploy does not update the desktop app's bundled copy. Recent web and Android source uses Cloudflare STUN unless the device or room selects another server; this does not mean every installed version has updated. Whichever STUN server is selected sees the device's IP address and port and carries no call media. A private TURN server may also answer STUN for devices configured to use it.

4.4 Data left from closed services

The file store and meeting codes stopped on 22 October 2026, and on the same day we deleted what they held: 84 encrypted files, about 164 MB in all, each sealed on the sender's device, and the store of room links behind short codes. Two mirror copies of the files, on machines of our own that served them by hash over Tor, were deleted on 23 October 2026.

Copies can remain in the owner's encrypted, offline machine backups, which serve no downloads. They are retained by the owner's decision recorded in the closure record.

4.5 Call relay settings and private deployments

You can enter a relay address, username and password under Settings, Connections, Call relay (TURN). These are settings for your device, not a public KithMoot relay account. The login is used with the relay addresses saved alongside it; it is not added to room invitations or published to Nostr. The web app keeps it in this browser profile's local storage. Android keeps it in a Keystore-encrypted file excluded from backups. Removing the relay deletes its saved login.

The relay receives your IP address, authentication identity, connection timing and traffic volume. It forwards encrypted call packets and is not given the WebRTC session keys. The relay's operator decides what metadata it keeps. Review that operator's privacy information and terms; this notice does not promise that an independently chosen provider keeps no logs.

A separate authenticated private relay is running for an arranged personal call. It is not offered through the public app's defaults or a public credential issuer. Its coturn and container logging are disabled; host and hosting-provider network logging have not been audited. Access and privacy arrangements for this private deployment are handled separately from the public software.

4.6 What the app keeps on your device

The app stores what it needs to work in your browser (or, in the desktop app, in its profile on your computer; Android uses its own private storage). None of it is sent to us. (If you sign in with a signer that can encrypt, your saved-room bookmarks and read positions are also published to relays, encrypted to your own key, so your other devices can follow them.) It lives in the browser's local storage and IndexedDB, and in a service worker cache that lets the app load offline. It includes:

  • the rooms you have saved, with their links, which contain the room's first secret key, and the device keys, seal keys and credentials the app makes for each room;
  • for rooms this browser created, the secret that lets it manage the room;
  • the latest room keys the app has worked out, and an archive of room events you have received, still encrypted to the room, kept in IndexedDB under a key the browser will not export;
  • messages waiting to be sent, kept for up to 24 hours;
  • your display name, pinned rooms, contacts and blocked people, read positions and your settings: text size, send delay, call devices and effects, relay lists, the call relay login and STUN choice (section 4.5), and the privacy choices in section 7;
  • if you sign in with a Nostr signer, the sign-in details the signer library keeps so you stay signed in (your public key, the method and, for a remote signer, its connection link and a client key) under the signet:login. prefix.

Much of this is held as ordinary, unencrypted local storage, so anyone who can open your browser profile or computer can read it. We do not set advertising or tracking cookies and the app does not use storage to track you. Storage the app needs in order to work does not need your consent. Clearing the site's data in your browser, or choosing Forget this browser in the app, removes it, and with it your access to saved rooms on this device unless you have their links.

5. How long we keep information

The public web server keeps no access logs (section 4.1). The former public STUN listener is stopped. Device-selected relay operators have their own retention arrangements (section 4.5). If you have written to us, that correspondence is kept for as long as we reasonably need it, and you can ask us to delete it.

6. Your rights

Because we hold so little that identifies anyone, most requests will come back "we do not hold that", which is itself the answer to a request. Where we do hold something identifiable to you, you can ask us to give you a copy, correct it, delete it, or restrict or stop using it. We will answer within one month.

Send requests to the address in section 1.

Content in a room. We cannot delete a message, a file or a call from a room, because we never held it. To have something removed, leave the room, ask a keeper who runs it to remove you or close it, or, for your own signed public events, use the in-app tool that asks relays to delete them.

You can complain directly to us about our handling of personal data using the contact in section 1. You can also complain to the Information Commissioner's Office (ico.org.uk).

7. Who else receives data

  • Public Nostr relays, including the independent relays the app suggests by default and any a room's creator adds, receive the ciphertext, device keys and timing any room necessarily produces to function.
  • Our hosting provider, which hosts the public app, website and update files.

The app also makes your device contact the following. Each learns your device's IP address and the time, as any web request does.

  • A STUN server, in a call. A client configured with stun.cloudflare.com asks Cloudflare, Inc. in the United States for your device's public address. The web app and kithmoot-agent select it by default, as do recent Android sources. Desktop through 0.1.101 bundles the older default; desktop 0.1.102 and Android 0.6.106 use Cloudflare STUN. Defaults in installed releases may differ. It learns your IP address and port and when the app makes the request. It carries no messages, files or call media. To choose a STUN server, use Settings, Connections, “Your STUN server”, where available. A selected device relay or a room's call-server settings can also determine which STUN server is contacted. Cloudflare, not us, decides what it keeps; its privacy policy is at cloudflare.com/privacypolicy.
  • A call relay you select. An independently supplied or self-hosted TURN relay receives the connection metadata and encrypted packets described in section 4.5. The relay is chosen on your device; the public app does not issue a ForgeSworn relay login.
  • A public file server, when you send a file. In the web app, and the desktop app that loads it, files you send go to blossom.yakihonne.com, a public server run by Yakihonne LLC in the United States, unless you choose another server, or "Nowhere", under Settings, Privacy, "Where files go". The first time your device sends a file, the app names the server and says what it sees, and nothing goes to it until you press Send. Your file is encrypted and padded on your device first, so the server cannot open it. The server receives the encrypted file; its size, rounded up so it is not exact; the upload, signed by a key made for your device in that room, which lets the server tell that uploads in one room came from the same device; your IP address; and when files are uploaded and opened. Anyone who opens the file, the people in your room included, connects to the same server, which learns their IP addresses too. Yakihonne, not us, decides what it keeps and for how long; its terms are at yakihonne.com/terms. Your choice, and the address of the server it names, are saved on your device so the app does not ask again. If a later version changes the default server, the app asks again before sending anything to the new one. A copy of KithMoot built by somebody else may use its own default server instead, and the app names that server in the same way.
  • Signet, if you sign in with it. Choosing Signet opens or links you to mysignet.app, the website of the Signet signer service. It learns your device's IP address, the time, and a sign-in request that names KithMoot, a return address, a one-time challenge and, where relays carry the sign-in, the relays to use and a temporary public key made for that sign-in. Your signer then handles requests from the app to sign, and to encrypt saved-room data, over the relays named in the request (relay.primal.net is always included), so it sees those requests. Signet's own privacy information covers what it keeps; this notice does not. The web app does not contact mysignet.app unless you choose this sign-in.
  • GitHub, when you unlock a member sticker pack. If you are signed in and ask to unlock a member pack, your signer signs a short proof that stays on your device, and the app then downloads a public registry file from raw.githubusercontent.com. GitHub learns your device's IP address, the time and that the file was fetched. The request carries no cookies or referrer, and your public key is not sent. Nothing is requested unless you ask.
  • Relays asked for public profiles. To show people's chosen names and pictures, the app asks for the public Nostr profile of the people it shows you: those in a room, in your private chats list and in People, and, if you already know them, whoever sent you an invitation. It asks three public relays: purplepag.es (a relay that gathers profiles), relay.damus.io and relay.primal.net. For the people in the room you have open it also asks that room's own relays. Each learns the public keys it was asked about and the address the question came from. The room itself keeps those keys inside its encryption; this lookup is what hands them to relays in the clear, and a relay that also carries the room can link them to it. A key your browser made for itself when you joined with only a name is never asked about.
  • The domain in a Nostr address, if you turn checking on. If a person's profile names a Nostr address (name@domain) and you have ticked "Verify Nostr addresses", the app asks that domain to confirm it. The domain learns the name asked about and the address the question came from, and can infer that somebody is looking at that person. No cookies or referrer are sent.
  • The host of a profile picture. A picture in a person's profile is loaded from whatever host that person chose. The host learns the address it was fetched from and when, and so that somebody is looking at that person. No referrer is sent. The picture's owner may run that host.

Profile lookups and pictures are on by default. Turn them off under Settings, Privacy, "Show public profile pictures and names", by clearing "Show public profile pictures, names and Nostr addresses". The choice is saved on your device. Turning it off stops further lookups and removes loaded profiles and pictures; it cannot recall a request already sent. Checking Nostr addresses is off by default, under "Verify Nostr addresses" in the same place.

The desktop app also makes your device contact:

  • Our site, for updates, as section 4.2 describes.
  • GitHub, for the Debian package. If you install the Debian or Ubuntu package, your system's package manager fetches KithMoot's updates from the project's releases on GitHub, on your system's own update schedule. GitHub learns your device's address, the time, and that it is fetching KithMoot.
  • Google, in desktop versions before 0.1.91, on Windows and Linux. The spellchecker built into Electron, the framework the desktop app runs on, downloaded a dictionary for your language from a Google server, which learned your device's address, the time and the language asked for. Electron's documentation says nothing you type was sent. From 0.1.91 the app switches that download off, so it no longer contacts Google for spelling, and it has no spelling check on Windows and Linux. The app updates itself as section 4.2 describes, and the Debian package updates with your system. The Mac app uses the macOS spellchecker, which downloads nothing.

Every connection the desktop app makes, and a command to check each one, is listed on Check it yourself.

We do not use an email marketing service, an analytics company or an error-tracking company for this site.

8. Children

KithMoot has not set a minimum age. We do not knowingly collect personal information from children, and we hold almost no personal information from anyone (section 2). If you think a child has given us personal information, ask us to delete it, at the address in section 1, and we will.

9. Automated decisions

We make no decisions about you by automated means that have legal or similarly significant effects.
