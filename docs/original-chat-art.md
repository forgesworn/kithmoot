# Original chat artwork

KithMoot's everyday emoji picker starts with [ForgeMoji](forgemoji.md): familiar faces, hearts, thumbs up/down and other recognisable Unicode meanings, including selectable human skin tones. Messages and reactions keep their standard Unicode sequences. The character artwork has its own collection rather than replacing everyday emoji.

The character collection includes 24 original reaction stickers, three Donkey stills and four acted GIFs. The initial sticker artwork was generated with the explicitly selected `gpt-image-2.5-sunburst` model; prompts and source sprite sheets are kept in `app/artwork-prompts/` and `app/src/assets/kithmoot-original/`. The Donkey stills come from the Blender performances. The separate 600 pack retains its explicit Nostr member unlock and picker-only gate. Existing Unicode and character shortcode reactions remain readable; flags are omitted from the picker.

The coffee animation is an original editable 3D interpretation of the sticker, modelled and animated in Blender on the M4. Its six-second performance includes a sip, contented pause, caffeine shock, coffee spill and guilty glance. The face, hands, arms and mug move separately. The committed GIF is transparent, 512 pixels square, 144 frames at 24 fps and under six megabytes. Its static preview also comes from the Blender master. Source scripts and regeneration instructions are in `artwork/animation/coffee/`. The other 23 flat rotating/bouncing GIFs are excluded from the picker; their packaged files remain available for existing messages.

Donkey has three performances: a snorting laugh, an embarrassed facepalm and a Bitcoin coin toss and catch. The orange quadruped, tall ears, black mane and tail, cream muzzle and dark hooves follow TheCryptoDonkey's familiar Donkey artwork. Each transparent 512-pixel GIF has a matching still for sticker use and reduced motion. Editable source and export instructions live in `artwork/animation/donkey/`. The catalogue marks reviewed animations explicitly, so adding an entry never enables an old flat GIF by accident.

The composer uses one tray with Emoji, Stickers and GIFs tabs. Emoji insertion keeps the tray open for repeated choices; reaction choices close it. Familiar, Recents, ForgeSworn, Characters and More emoji collections remain accessible on narrow screens and in landscape. Hand colour is remembered locally. Phone browsing starts with the keyboard dismissed, and search opens it explicitly. Media thumbnails open a larger preview; Add stages a bundled catalogue reference, followed by the separate Send action. Built-in artwork needs no upload or storage consent. Search and artwork browsing use bundled files without a third-party catalogue request.

Browsing and searching the local emoji, GIF and sticker collections makes no third-party graphics requests. Fresh PWA installations precache the active WebP chat-art and ForgeMoji derivatives and all responsive 600 variants from their own origin. The original GIF/PNG files remain deployed for wire compatibility, native packaging and one-time local fallback, but are not in the fresh chat-art/emoji precache. An upgrade first copies originals already present in an old Workbox precache into the `kithmoot-original-artwork-v1` runtime cache, without network access; a failed copy aborts installation. Same-origin original URLs use stale-while-revalidate afterwards.

Web previews always use a static WebP preview when reduced motion is requested, including expansion. Other displays prefer the full-size lossless WebP, with `.animated.webp` distinguishing an animation from its still. If a preferred WebP cannot load or decode, the renderer removes its candidates and restores the original URL once. Personal attachment and decrypted blob flows retain their original single-URL behaviour. Desktop and Android package the original assets; native GIF previews respect disabled system animation and stop with the view lifecycle.

Choosing a personal file uses the existing encrypted attachment flow and storage consent. Built-in stickers and GIFs send only their encrypted catalogue references; recipients display their own bundled artwork. Browsing the pack does not grant storage consent, and no third-party credit or URL is inserted into the draft.

To regenerate the 24 character stickers and the complete catalogue metadata, run `node scripts/build-original-chat-art.mjs` with FFmpeg installed. This preserves and verifies the reviewed coffee and Donkey animations and previews, and never recreates the old flat GIFs. To supply a reviewed coffee Blender export instead, add `--coffee-export /absolute/export-folder`; the folder must contain `coffee.gif` and `coffee-preview.png`. Donkey export hashes and byte sizes are pinned in `artwork/animation/donkey/reviewed-assets.json`. The script verifies pinned hashes, 512-pixel dimensions and GIF size before changing assets. A new animation must be reviewed before its pinned hashes are updated. `node scripts/build-original-chat-art.mjs --check` verifies packaged artwork and metadata without modifying assets.

After any reviewed original-art change, run `npm run artwork:generate` with `cwebp`, `gif2webp` and `ffprobe` installed. These are maintainer tools, not runtime or ordinary CI requirements; the committed receipt records their exact versions and options. The current profiles use libwebp lossless encoding for full-size stills and animations, and one libwebp resize followed by lossless encoding for each 64/128/256/384px 600 thumbnail. Do not substitute the installed FFmpeg's WebP support or a lossy/mixed profile without a fresh visual and timing review. Commit all 211 derivatives and `artwork/derivatives-v1.json` with their source changes.

The measured derivative set is **18,108,838 bytes (17.270 MiB)**: 28 chat-art stills at 2,366,560 bytes, four animations at 11,194,326 bytes, 163 ForgeMoji stills at 3,788,732 bytes and 16 responsive 600 thumbnails at 759,220 bytes. Their corresponding source inputs total 48,477,526 bytes, a 30,368,688-byte (62.64%) reduction. The thumbnail comparison counts each 1024px source once for each of its four sizes. These are source/derivative measurements, not before/after precache or deployed-artifact totals.

`npm run artwork:check` checks both original artwork and every receipt source/output hash, dimensions, RIFF chunks, animation frames, per-frame durations, infinite looping, unexpected files and size totals without running image tools or modifying files. `npm run build` runs that check before Vite and audits the built originals, derivatives and precache afterwards; the direct built audit is `node scripts/build-artwork-derivatives.mjs --check-built`, with `VITE_DESKTOP=true` for `desktop/web`. The built audit reports exact deployed and precache bytes. Retaining originals increases deployed artwork bytes even while fresh startup/precache bytes fall, so those measurements must not be conflated or described as a smaller complete artifact.

To update the explicitly selected native checkout, run `node scripts/sync-original-chat-art.mjs --android /absolute/native-checkout`. The generated manifests pin original file sizes and hashes; web selection rejects substituted URLs, display derivatives or bytes. Native selection accepts only the compiled catalogue and exact APK asset lengths. WebP is a web/display derivative only: do not add its fields to native catalogues or replace native PNG/GIF inputs. ForgeMoji has its own explicit snapshot synchronisation command documented separately.

The collection is a finite local pack. People can also attach their own images and GIFs through the existing file picker.
