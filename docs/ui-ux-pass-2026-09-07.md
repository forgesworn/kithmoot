# UI/UX pass — 7 September 2026

The target is a workspace that makes everyday conversation easier: enter a
room, find the right conversation, catch up, reply, and return to work without
losing context. “Beat Slack” needs evidence from those journeys and people
using them; a feature list or passing browser suite does not establish it.

## Catching up

The existing UI had visible unread badges, but selecting a conversation
always jumped to the bottom and cleared them. Switching away while reading
also lost the place. That made the badges poor guides in busy conversations.

This change:

- Remembers the first visible message and its offset for each conversation
  during a room visit, before changing the toolbar or composer layout.
- Opens unseen activity at a New messages divider. An existing reading
  position takes precedence, so returning does not interrupt reading.
- Offers Next unread with the destination and count, including conversations
  beyond the edge of the phone's navigation strip.
- Keeps Jump to latest available when reading above the bottom; keyboard
  focus returns to the conversation after using either catch-up action.
- Counts resolved messages instead of treating edits as extra unread messages.
  Reactions, retractions and private invitation events do not inflate the count.
- Keeps long destination names within the phone layout; the full label remains
  the accessible name and tooltip.
- Keeps catch-up and search on one row on short phones, with picture
  preferences still available in Room details. Empty composers use one line
  even when the conversation name makes the placeholder long.

Reading positions are scoped to a connected room visit. Conversation read
sets now remain with their room and account while switching within this tab.
This does not add background history loading or persist draft text.
The divider stays in place while reading and resets on switching conversations.
Existing bottom-of-conversation read semantics remain: reaching the bottom
marks the loaded conversation read when it is visible and no dialog covers it.

## Finding messages across a room

Search is now visible in the conversation toolbar and covers all loaded room
conversations by default. Results name their conversation; selecting one opens
the original message in context, including the latest version of an edited
message and nested replies. Retracted messages do not appear.

A conversation filter and Files only narrow the results. Back to results keeps
the query, filter and result position while moving between contexts. The first
100 results have an explicit Show more action. Incoming messages update results
without stealing focus; closing search clears the query. Room details retains
the shortcut for searching only the current conversation.

Search reads already loaded, decrypted history: up to 500 messages per
conversation from the last 30 days. It does not load other rooms or fetch files.
The coverage explanation is available inside search. Phone layouts cover both
themes, long conversation names and 200% text; Safari reopening uses the search
field as the dialog's initial focus target.

## In-app confirmations

The app's 16 browser `confirm()` calls now use a shared styled dialog. Each
question has a descriptive action, a safe initial Cancel/Keep working button,
keyboard focus containment, Escape and backdrop cancellation, and focus return.
Destructive actions use the existing danger colour. Long room names and the
browser-room import list wrap inside a scrolling dialog on small screens.

Messages and calls continue while the person decides. Room and account changes
invalidate pending room actions. Pairing now awaits approval, remembers each
device decision for the invitation's lifetime, and ignores duplicate requests
while a question is pending. Closing the pairing host prevents an outstanding
approval or signer response from issuing a credential. A fresh invitation
allows a cancelled pairing to be tried again.

Draft discard, leaving, room switching, bookmark import/forget, message
retraction, failed-send dismissal, room administration, invitation replacement,
device pairing and update/reload use the same component. Browser-controlled
`beforeunload` remains for an actual tab close or browser reload with unsent
work; a website cannot customise that warning.

## Reading a busy conversation

Each writable message now has one visible actions button in place of repeated
Reply, Edit/Retract and three unused reaction buttons. The anchored action panel
contains Reply, the author's edit/retract controls, and all eight supported
reactions. Reactions that people have used stay directly on the message,
including the existing agent receipt details.

Consecutive messages share the visible sender heading when their author, claimed
name, owner, agent status and message kind agree, and they are less than five
minutes apart on the same day. Matching display names alone never group people.
Threads, system lines, retractions and unread dividers preserve clear boundaries.
Every message retains its timestamp and accessible sender identity.

The action panel stays attached to its original message while the log repaints,
updates its excerpt after edits, and closes if that message disappears or is
retracted. Escape returns focus to the message; Tab reaches every action;
clicking back into the composer dismisses it without changing the draft.
Selecting Reply or Edit moves focus into the composer. Reply previews resolve
the latest text, and long names wrap at enlarged text sizes without pushing
Cancel beyond the screen. An open action panel does not mark covered arrivals
read automatically.

## Starting a conversation with other people

Invite people now sits beside search in the conversation toolbar. Profile
picture preferences remain in Room details. The arrival screen and empty Chat
point to the invite action, and rooms restricted to named members do not show
it as a way to admit more people.

The invitation sheet puts the link and Copy link first, with feedback inside
the sheet. Successful clipboard writes are acknowledged; when both automatic
copy methods fail, it explains how to copy manually. Invitation availability,
link replacement and QR display remain available. The same controls return to
Room details when the sheet closes, so there is one current invitation URL.
The link-sharing privacy explanation stays available in a disclosure.

A new browser journey creates a group, copies its invitation, admits a second
person in an independent browser context, and receives their message while the
sheet is still open. It also checks copy failure, QR drawing, keyboard focus,
Escape/backdrop dismissal, preserved draft text, both themes and enlarged text.

## Switching rooms with drafts

The workspace and room picker now switch within the current document. Each
room reconnects after the previous session leaves, preserving its drafts,
text selection, staged files, reply/edit context and conversation read sets
in memory under that room and account. Project filters also stay in place.
Draft text and file keys never enter local or session storage. Reloading,
closing or explicitly leaving the tab still discards them, with the existing
warning covering drafts in every visited room.

A switch stops the old session, relay pool, invitation/pairing hosts, media
pipelines, peer connections, remote playback and room timers. Search and action
panels clear; permissions, catalogues, channels, roster and epoch state start
fresh. Old room callbacks cannot populate the next room. A delayed microphone,
camera or screen permission result is stopped even if it arrives after the
switch. Camera pipelines also reject a device change that finishes after stop.
Live calls use the app confirmation; cancelling keeps the call, and accepting
enters the next room with media off. Carrying for peers resets to off too.

Chat uploads and pending or failed sends still need to finish, be stopped,
or be explicitly dismissed before switching. Their existing controls stay
available, and New tab remains an option. The picker updates as sends settle.
This is deliberate: a prepared send owns the old room's transport. This change
does not keep hidden room sessions alive or move a send to another room.

Failed admission offers a direct Back to [previous room] action on phones and
desktop, restoring its draft after rejoining. Retrying an invitation from this
flow also stays in the document. An identity change prevents automatic joining.
The legacy, account-bound two-minute reload intent remains readable for pages
opened by the previous version; new switches no longer write it.

## Reading across room switches

Reading positions now stay in memory per account, room and conversation.
Leaving freezes the visible message and its offset before the old session is
torn down. Rejoining restores the position after the room is visible, including
when history arrives later. Empty reconnect renders cannot replace the saved
position or mark unseen activity as read.

Jump to latest stays available while waiting for the old message. Choosing it,
or deliberately scrolling, gives control back to the reader. If that message
is no longer retained, the reader can still move straight to the latest
messages. Following the latest messages also survives the log resizing after
room navigation or a viewport-height change. Positions do not survive closing
or reloading the tab.

## Shared work follows the conversation

The Work panel now keeps unfinished objectives, criteria, action inputs and
card notes in memory per room and participant. Switching rooms restores that
room's form; closing or reloading warns about unsent work in visited rooms.
Submitted assignment journals retain their existing encrypted storage.

Creating an assignment requires an explicit owner. Missing fields show inline
feedback and focus the field instead of invoking browser validation bubbles.
Discarding a form or an obsolete note uses the app confirmation. Cancellation
and handoff sit under Manage assignment, leaving the current action prominent.
Incoming updates preserve the focused note, selection and expanded sections;
notes from a completed step remain available to copy or explicitly discard.
The panel wraps at 320 pixels and enlarged text, in both themes.

An active submission blocks room switching until it settles. Failed delivery
exposes Retry and prevents another mutation while the saved update is pending.
The form remains editable after failure. A successful retry clears only the
form that produced that update, preserving a newer draft. Async completion is
bound to its original session and cannot reset the next room's form.
