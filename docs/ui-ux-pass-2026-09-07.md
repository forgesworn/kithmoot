# UI/UX pass — 7 September 2026

The target is a workspace that makes everyday conversation easier: enter a
room, find the right conversation, catch up, reply, and return to work without
losing context. “Beat Slack” needs evidence from those journeys and people
using them; a feature list or passing browser suite does not establish it.

## Catching up

The existing UI had visible unread badges, but selecting a conversation
always jumped to the bottom and cleared them. Switching away while reading
also lost the place. That made the badges poor guides in busy conversations.

This change:

- Remembers the first visible message and its offset for each conversation
  during a room visit, before changing the toolbar or composer layout.
- Opens unseen activity at a New messages divider. An existing reading
  position takes precedence, so returning does not interrupt reading.
- Offers Next unread with the destination and count, including conversations
  beyond the edge of the phone's navigation strip.
- Keeps Jump to latest available when reading above the bottom; keyboard
  focus returns to the conversation after using either catch-up action.
- Counts resolved messages instead of treating edits as extra unread messages.
  Reactions, retractions and private invitation events do not inflate the count.
- Keeps long destination names within the phone layout; the full label remains
  the accessible name and tooltip.
- Keeps catch-up and search on one row on short phones, with picture
  preferences still available in Room details. Empty composers use one line
  even when the conversation name makes the placeholder long.

Reading positions and conversation unread counts are scoped to this room
visit. This does not add cross-room history loading or persist draft text.
The divider stays in place while reading and resets on switching conversations.
Existing bottom-of-conversation read semantics remain: reaching the bottom
marks the loaded conversation read when it is visible and no dialog covers it.

## Validation

Node 24: type checking and the production build pass; all 1,377 unit tests pass.
The production build retains the existing JavaScript chunk-size warning.

The new workspace browser journey exercises a busy room, background agent
messages, a preserved draft, arrival during catch-up, returning to the same
visible message, Jump to latest, editing a read message, a read-only
conversation, long channel names and a 320 × 540 viewport. Existing workspace,
draft, search and message-reliability checks are run alongside it.

The final workspace, draft, search and message-reliability run passed 35 checks
in Chromium/Firefox and 17 in WebKit. The two skips reserve the microphone
search test for Chromium, where it passed. The new catch-up test was then
tightened to verify editing while reading above the bottom, so automatic
marking cannot conceal a false unread count; it passed in all three engines.
