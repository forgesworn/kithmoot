# Creating projects and adding rooms

Android previously labelled device-only room filing “Add to a project”. Web and desktop opened a new project editor rather than a chooser for an existing project. Projects were also hard to discover before sign-in or before saving rooms.

Projects and New project are now reachable from the web home and desktop room rail. Android offers Projects before sign-in, with a direct Sign in action. New project opens a draft while project history is connecting; saving still requires the account signer and verified history. The editor displays the actual sync error or the pending connection requirement.

The room menu opens the shared-project chooser. The owner can add the selected persistent room to an existing project or create a new one. Existing people, agents and room invitations are preserved. The invitation-sharing consequence is shown before saving. Local grouping remains available under Group on this browser or Group on this phone.

The browser acceptance journey creates an empty project, adds a persistent room to the same project, checks membership, then reopens the app and reads the encrypted directory. It passes in phone-sized Chromium and the desktop layout. A separate check keeps New project discoverable and explains a signer without NIP-44 support. Both installed-app Android project journeys pass on a disposable API 35 emulator, including people, agents and account guards. Physical-phone acceptance remains outstanding.
