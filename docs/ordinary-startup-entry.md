# Ordered ordinary startup entry

The application index has one application module entry. It permits the legacy
text-size, call-folds and main modules, in that order, only after a pure native
absence check. Every existing ordinary database holds intact, including an
empty, malformed, newer or unfinished database. This is an initial entry guard;
it does not mount the protected member interface or migrate a profile.

The tiny initial graph imports no SDK, owner, signer, snapshot or crypto module.
It acquires shared leases on the fixed migration lock and then the ordinary
write lock, matching the real migration writer's order. The absence observation
is one-use: only a native creation with old version zero and new version one,
explicitly aborted and followed by both transaction abort completion and the
open request's AbortError, can pass. Successful opens close and hold. Unknown
or blocked requests stay joined. No timeout proves absence.

Immediately before the first legacy import, commitment irreversibly removes
the application's release path for both locks. A late or partially evaluated
module cannot outlive its exclusion from protected writers. Neither pagehide
nor an import error releases a committed lease; the browser releases it when
destroying the document. Before commitment, closure revokes startup, joins the
native request and releases both leases. Multiple legacy pages share the locks;
a real migration or ordinary owner writer waits until all those documents go.

A capture-phase pageshow handler precedes the legacy graph. An unexpected
persisted restoration holds, stops later pageshow handlers and reloads through
the guard. Native navigation tests separately record actual pagehide persistence
and fresh reclassification; synthetic transition tests exercise the defence
without being presented as actual BFCache acceptance.

The legacy path deliberately installs no protected-client compatibility
responder. A future protected screen must use the origin-wide fence and actual
role-specific startup/lifetime controllers. It must not hand protected storage,
a raw SDK signer or a broad Session to the legacy main graph.

The native fixture tests use real IndexedDB and Web Locks with synthetic signed
room state and observable replacement legacy modules. Separate tests run the
actual Vite build: existing protected state loads no legacy chunk, SDK entropy,
Storage reader, provider or socket, while delayed real module evaluation keeps
both leases. These are source and automated-browser checks. Protected UI,
remaining carriers and consumers, deployment, physical acceptance, independent
rollback continuity and production MLS remain separate open work.
