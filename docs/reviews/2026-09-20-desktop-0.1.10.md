# Desktop preview 0.1.10 — 20 September 2026

This candidate includes cleanup of screen and audio tracks returned after the
sharing-area chooser is cancelled, and the sustained-drawing repair already
present on main. It introduces the first Developer ID signed and notarised Mac
archive. Linux x64 and ARM64 archives retain the preview distribution model.

## Packaging and signing

The packager's obsolete `signAsync` import prevented packaging with the pinned
`@electron/osx-sign` 2.7.0. It now uses that library's documented async `sign`
export. Both the real signing run and packaged-app smoke completed.

The account holder created a Developer ID Application certificate from a local
CSR. The existing App Store Connect API key successfully authenticated to the
notary service. App Store signing identities were retained; the new identity
is installed in a dedicated local release keychain. Private keys and credentials
are outside the repository.

## Candidate checks

- Native Electron smoke passed on the development build and the signed packaged
  app: frame creation, resize, chooser gesture, closure, sandbox bridge,
  no renderer Node APIs, CSP, traversal denial and profile persistence.
- All five native/browser journeys passed: bidirectional synthetic audio/video
  and chat; cancelling close and leaving a call; notification privacy and badge
  behaviour; room switching and separate drafts; relay-only failure handling.
- Linux package versions and ELF architecture headers verified for x64 and
  ARM64. Both carry identical app.asar contents. This release's Linux archives
  have not been run on a physical Linux desktop.
- Capture cancellation and crop/audio browser checks are recorded in the
  [capture fix review](2026-09-20-desktop-capture-cancellation.md).

## Remaining acceptance

Actual display capture, audible system sound, remote-call echo exclusion,
drawing alignment and permission continuity need physical Mac checks.
A first upgrade from an ad-hoc preview may require granting permission again.
There is no automatic updater. Signing and notarisation do not close these
product acceptance checks.

Publication and deployment must be verified against these exact artifact hashes
separately from the candidate evidence above.
