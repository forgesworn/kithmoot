# Desktop preview 0.1.10 — 20 September 2026

Desktop chat and its composer now fill the available room width. The area-sharing
frame has four 28px corner handles, a clear draggable Move bar, and arrow-key
movement/resizing. Its native window uses the screen-saver always-on-top level
and is visible across macOS workspaces, including fullscreen spaces. The crop
excludes the wider border, toolbar and footer.

Drawing labels now form one bottom colour legend entry per author, instead of
one label per transmitted segment. Entries fade with that author's last visible
stroke and disappear on expiry or clear. Capture cancellation still stops late
screen/audio tracks, and a cancelled or replaced native frame cannot complete an
older pending source enumeration.

The Mac archive is Developer ID signed and notarised. Linux x64 and ARM64
archives retain the preview distribution model.

## Relay recovery found during release CI

Run 35499093729 passed 180 Chromium checks but failed the relay-outage soak:
`connection failure: connection timed out` was reported as an explicit refusal,
so a message sent as the relay returned was never retried. The dependency emits
that handshake failure as a string, while an actual relay `OK false` is an
`Error`. The fix recognises the exact handshake-timeout string and preserves
the existing 20-second retry budget. It does not broaden matching to arbitrary
relay rejection text.

A deterministic regression reproduced the exact failure before the fix. All
36 relay/authentication tests passed afterwards, including successful recovery
of the same prepared event, timeout exhaustion, and an explicit refusal that
quotes the same timeout wording. The original browser soak also passed in
2.1 minutes: video survived the 90-second outage and chat arrived after the
relay restarted.

## Remaining acceptance

Actual display capture, audible system sound, remote-call echo exclusion,
drawing alignment and permission continuity need physical Mac checks.
A first upgrade from an ad-hoc preview may require granting permission again.
There is no automatic updater. Signing and notarisation do not close these
product acceptance checks.

Publication and deployment must be verified against these exact artifact hashes
separately from the candidate evidence above.
