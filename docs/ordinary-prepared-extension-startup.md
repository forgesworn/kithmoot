# Prepared extension account restoration

`OrdinaryMemberExtensionStartup` restores the selected NIP-07 account through
an actual SDK discovery call before prepared renewal recovery. The caller
supplies native browser/tab owners and an identity-free six-field selection.
The controller captures strict data descriptors, input identities and provider
references, reserves the native tab synchronously and retains that reservation
until all unabortable work and closing have joined. It never returns an SDK
session, raw signer, native record view or generic executor.

The private owner factory authenticates exact prepared E: coherent browser/tab
frames and control, whole-origin classification, the inverse predecessor,
selected account/invitation/link/keep, historical first credential expiry,
request time/floor, native SDK metadata and the retained signed foreground
proof. These checks grant only one account discovery. They create no fresh
proof, credential, native write or entropy and install no ordinary read cache.

Signet's separate versioned NIP-07 discovery boundary first captures provider
references, then revalidates those references in `prepare()` outside native
authority. The owner repeats its actual E/native/liveness decision afterwards.
Its synchronous transaction callback starts only the captured provider effect
and returns no Promise. The outer owner/root lifetime joins the provider and
the entire SDK promise, including SDK result checks and signer construction,
then reauthenticates exact E and current selection before any private handoff.
An unabortable request remains joined after refusal; a created but refused raw
signer is closed. Provider metadata getters cannot bypass the last selection
check or the post-SDK native handoff.

The restored SDK is handed privately to `OrdinaryMemberStartup`, which performs
fixed prepared recovery, fresh ordinary foreground/role construction and
selected material loading. Only one scoped member may subsequently be opened.
Close joins that member and its work before closing the owned SDK and wiping
the invitation copy. Native tab expiry and the historical SDK deadline revoke
idle controllers as well as later calls. Concurrent opens for the same tab in
this application realm refuse while discovery or closing is pending; actual
native locks and exact records independently fence cross-context work.

The browser tests use real encrypted IndexedDB, Web Locks, the actual packaged
SDK and signed protocol events. The relay is a synthetic authority which
validates the actual epoch request and encrypts the grant to its credential.
This is browser/source evidence, not real relay or physical-device acceptance.

`signet-login@0.18.2`; see [SDK provenance](ordinary-sdk-provenance.md). Earlier
local overlay checks remain distinct from fresh registry CI and deployed acceptance.
