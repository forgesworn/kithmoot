# Physical classification and navigation handoff

`ordinary-physical-snapshot.ts` selects reserved `kithmoot` dot, colon and dash
roots and the Signet login root. It rejects unknown names, unsupported versions,
aliases, wrappers and owner placements. Every recognised name has exactly one
family and custody category. Unrelated origin records remain outside that scope.
The classifier supplies the selection policy; classification alone does not
validate the ordinary family values or establish a complete coherent image.
Every protected partition still requires its strict semantic validator.

Identity rows belong to the browser owner. Current main writes device keys,
paired credentials, own credentials and seal history through its localStorage
DeviceStore. Its sessionStorage fallback readers do not prove a supported tab
producer. Such raw tab identity rows hold intact for explicit recovery. The
account wrapper and device-owner marker describe the reviewed scoped destination;
their grammar does not authorise conversion or waive the identity validator.
Pending rows support both owners but must be validated as one paired queue.

There are only three raw revision-signal exceptions, all browser-owned:
`kithmoot-mls-vault-v1.revision`, `kithmoot.mls-coordinated-vault.revision` and
`kithmoot-rendezvous-vault-v1:revision`. Their values must match the current
lowercase version-4 UUID writer. Generic vault constructors can form other names,
but their current consumers do not write revision signals. Those other names
hold. The exact temporary-owner marker is tab-only and requires lowercase
64-hex. Neither UUID syntax nor marker syntax proves randomness or authority.

Text size remains protected, with exactly `standard`, `large` and `huge` values.
No visual exception is adopted. `call-tab-lock.msg` also remains protected inert
metadata: canonical claim/release/probe message, UUID tab, timestamp and random
fraction. Callable lock methods can persist empty or long opaque keys; custody
does not infer a room/device binding. Moving this row would break the current
storage-event fallback; runtime integration must replace or remove that protocol.

The physical preflight copies the snapshot and applies the 8 MiB UTF-8 per-value,
16,384 protected-record and 32 MiB prospective raw-image limits before parsing
special values. The authenticated frame separately checks its full encoded size.
Navigation shape validation also checks its per-value limit before JSON parsing.
No pruning, clock, entropy, key allocation, owner construction, networking or
Storage mutation belongs to these checks.

Navigation rows belong to a separate tab partition. Capture takes the complete
physical snapshot before partitioning and retains its exact access names/bytes
privately. The public frozen context contains only counts; copied tokens,
changed/different access partitions, physical-owner changes and duplicated raw
navigation dispatch hold. Consumption lives in the access module; there is no
public raw-link visitor. Candidate bytes cannot change when the caller changes
the source map. This binds navigation to its access partition, not every other
family in the future complete image.

Opaque way-back links and empty switch hashes remain inert custody. Only when an
access row lacks a binding does the access consumer parse the retained candidates
with its existing strict link parser and verify the actual invitation, room and
delegation. It never defaults an empty hash or uses a navigation account reminder
as authenticated identity. A token is not current admission or startup authority.

Existing raw startup-link and bookmark retained-room parameters remain family
helper APIs. The complete composer must replace their arbitrary caller handoff
with private provenance-bound contexts and bind accounts, devices, credentials,
epochs, traffic, drops and inner messages across both owners. This source slice
does not implement that composer or the production root.

Native tests prepare the actual three revision writers, text-size module/change
control and call-lock storage fallback before blocking effects. Main navigation
writer cuts use the existing source-extraction fixture with synthetic globals.
Verified-grant cases use the real admission encoder/decoder with synthetic keys
and test-created navigation rows. They exercise partition binding and refusal in
Chromium, Firefox and WebKit; they are not full startup or independent acceptance.

Remaining integration includes complete same-image bindings, both-owner raw
preflight before tab-marker allocation, protected startup before independent
modules, actual client/capacity fences, awaited consumers/effects, authenticated
signer restoration and coordinated forgetting. Main is unchanged. This work is
unpublished and does not close DG08 or any physical/release gate.
