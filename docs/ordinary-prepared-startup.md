# Prepared member-renewal startup recovery

This source controller runs before ordinary bootstrap open/read. It captures
one selected actor, owner pair, invitation, link, retention choice and signing
identity. An account supplies its genuine currently selected SDK session; a
visitor is signed using the exact native participant key. No new login,
credential timestamp or authority deadline is requested.

A private startup factory owns a one-use quiescent lifecycle root. That graph
can retain and join work, but its ordinary run/check/task boundaries refuse.
The exact authentication and signing promises are registered with the root,
both native owners and the private foreground adapter before any native await.
Ownership does not grant phase permission.

The owner authenticates the existing prepared E frames, dual control and
complete origin, then reconstructs inverse P on owned copies. Historical
snapshot validation remains inert. An opaque callback-local E token can only
validate the selected prepared foreground; it is not an ordinary read,
mutation, resource or adoption token. The one-use witness binds the factory,
root, owners, exact request, phase, frames, control, scopes and origin facts.

The account adapter exposes no ordinary signing or crypto capability. The
current session object, SDK method, public key, auth event bytes, generation,
deadline, display name and bunker material must remain unchanged and agree
with native E. The current v1 deadline must equal the historical deadline.
The frozen request must not be in the future and must retain the resume floor.
A different foreground deadline needs a separately reviewed journalled
reauthorisation transition.

Before signing material is allocated, the owner checks complete projected C
image sizes and every control-phase envelope size. It freezes one started
control cohort and authenticates its actual encrypted plaintext before writing.
The same native readwrite decision repeats the complete E, origin and role
checks before the single put. Exact prior can retry only the identical cohort
while live. Mixed or unavailable acknowledgement retains that cohort and the
origin lock until explicit retention repair. Exact started must be acknowledged
before one permanently latched SDK or native-visitor signing attempt.

A valid already-started result is independently verified and retained using
its preallocated control nonces. The encrypted result plaintext is checked
before the custody write. That result-only write can finish after revocation
without another signer invocation, fresh entropy, current-role inference or C
adoption. Close joins the real signer, crypto and unknown acknowledgement.
An operation already at provider-started without a result is never retried.

The controller can finish the existing fixed historical E-to-C and C-to-S
maintenance and return frozen `settled` status. Its temporary factory, signer
and graph then close. No Bootstrap, Session, carrier, images, keys or writer
escape. A live member still requires a separate fresh ordinary read and
current-role construction after S.

This is source work. Full application root mounting, SDK restoration at the
entry, guarded consumers, old-client fencing, independent rollback continuity,
current MLS authority, registry release and physical acceptance remain separate.
